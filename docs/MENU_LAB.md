# 메뉴 추천

FoodVOC의 **메뉴 추천** 탭은 식사 구분·식단가·고객층·원하는 방향·피하고 싶은 VOC를 받아 메뉴 조합 3안을 제안합니다.
계산은 모두 브라우저 안에서 이루어지며, 외부 사이트나 서버에 접속하지 않습니다.

## 파일 구성

| 파일 | 역할 |
|---|---|
| `src/data/menuMainItems.ts` | 메인 메뉴 54개: 분류, 차림 형태, 국물 여부, 면·튀김 여부, 계절, 맞는 식사·고객·방향, 강점, 생기기 쉬운 VOC, 어울리는 반찬·국, 운영 메모 |
| `src/data/menuSideItems.ts` | 반찬 40개: 역할, 어울리는 메인 분류, 생기기 쉬운 VOC |
| `src/data/menuSoupItems.ts` | 국 14개: 역할, 맞는 식사 구분, 생기기 쉬운 VOC |
| `src/data/menuVocRiskRules.ts`, `menuScenarioRules.ts` | VOC별 예방 포인트·점검 신호·운영 시나리오 문장 |
| `src/utils/menuRecommender.ts` | 점수 계산과 3안 선정, 반찬·국 고르기 |

## 데이터 원칙

- 메뉴명은 단체급식에서 흔히 쓰는 **일반 메뉴명**만 씁니다. 외부 사이트의 메뉴·평점을 가져오지 않습니다.
- 반찬·국의 VOC는 성질로 정합니다: 장·젓갈·장아찌류는 염도, 부침·마요네즈류는 느끼함, 식으면 맛이 떨어지는 부침은 보온 지연,
  익히지 않는 생채소·해산물은 위생, 잔가시·흙이 남기 쉬운 재료는 이물 혼입.
- 메인의 `bestSides`·`bestSoups`는 반찬·국 목록에 있는 이름과 같아야 점수에 반영됩니다.

## 고르는 방법

1. 계절이 맞지 않는 메뉴(물냉면·비빔국수·삼계탕은 6~8월만)를 뺍니다.
2. 고른 식사 구분에 맞는 메뉴가 3개 이상이면 그 안에서만 고릅니다.
3. 점수: 식사 구분 +4, 고객층 +3, 방향 +3, 단가(기본 단가 이하는 가성비 +2·프리미엄 −2, 높은 단가는 프리미엄 +2),
   고른 VOC가 메뉴의 약점이면 −5·아니면 +1, 야식·보온 지연·대기시간 조건에서 면·튀김 −8.
4. 같은 점수는 입력 조건에 따라 순서를 바꿔, 이름 순으로 늘 같은 메뉴가 올라오지 않게 합니다.
5. 3안이 같은 차림 형태(정식·덮밥·면·국물·세트)나 같은 분류로만 채워지지 않게 겹칠 때마다 점수를 낮춰 다시 비교합니다.
6. 국물 메뉴에는 국을 붙이지 않고, 나머지는 어울리는 국·식사 구분·VOC를 따져 3안끼리 겹치지 않게 고릅니다.
7. 반찬은 메인·국과 주재료가 겹치지 않게, 비슷한 반찬(감자류, 김치류, 계란류, 절임류, 생채소 샐러드류, 부침류)은 한 안에 1~2개까지만 고릅니다.

## 메뉴 추가 방법

`menuMainItems.ts`의 `mainTemplates`에 객체를 하나 추가합니다. 반찬·국 이름은 목록에 있는 것을 쓰고,
국물 메뉴면 `hasSoup: true`와 `bestSoups: []`, 면·튀김이면 `timeSensitive: true`, 계절 메뉴면 `months`를 적습니다.
